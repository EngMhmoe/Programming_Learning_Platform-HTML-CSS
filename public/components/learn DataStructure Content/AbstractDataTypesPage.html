Data Structure Programming

Abstract Data Types (ADTs)

Learn how Abstract Data Types describe what a data structure does, define its operations, and hide the details of how those operations are implemented.

Previous Next
Definition

What Is an Abstract Data Type?

An Abstract Data Type (ADT) is a logical model that describes a type of data and the operations that can be performed on it, without specifying exactly how those operations are implemented.

Focus on What, Not How

An ADT tells us what we can do with data. The actual data structure determines how we do it in a program.

Remember

An ADT is a logical description of behavior. It is not necessarily a specific piece of code or a particular way of storing data.

Main Concept

The Main Idea Behind ADTs

Think about using a TV remote. You press a button to increase the volume, but you do not need to know how the internal electronics work.

Increase Volume

You use a clear operation without needing to understand the internal implementation.

Public Operations

The ADT describes which operations are available to the user.

Hidden Implementation

The user does not need to know the internal details used to perform each operation.

Flexible Implementation

The implementation can change as long as the defined behavior remains consistent.

Key Difference

ADT vs Data Structure

These terms are related, but they do not mean exactly the same thing.

Abstract Data Type

What?

Defines the data's behavior and the operations that are available.

  • Defines allowed operations
  • Describes expected behavior
  • Hides implementation details

Data Structure

How?

Defines how data is organized and stored so that operations can be performed.

  • Organizes data in memory
  • Implements operations
  • Affects performance and storage
Simple Example

A Stack ADT describes the Last In, First Out (LIFO) behavior and operations such as push and pop. A stack can be implemented using an array or a linked list.

Components

Components of an ADT

An ADT describes the data it represents, the operations available, and the behavior expected from those operations.

01

Data

The values or elements managed by the ADT. For example, a Stack may contain numbers, names, or other values.

02

Operations

The actions supported by the ADT, such as adding an item, removing an item, searching, or checking whether it is empty.

03

Rules and Behavior

The rules that define how operations behave. For example, a Stack removes the most recently added item first.

Example 01

Stack as an ADT

A Stack follows the Last In, First Out (LIFO) rule. The last item added is the first item removed.

Stack Operations

How Does a Stack Work?

TOP
30
20
10
Bottom
push(30) Adds 30 to the top of the Stack.
pop() Removes and returns the top item.
peek() Returns the top item without removing it.
isEmpty() Checks whether the Stack contains no items.
Important

The Stack ADT defines the behavior of these operations. It does not require one specific implementation, such as an array or a linked list.

Example 02

Queue as an ADT

A Queue follows the First In, First Out (FIFO) rule. The first item added is the first item removed.

Queue Operations

How Does a Queue Work?

Front Rear
10
20
30

The item 10 entered first, so it leaves first.

enqueue(30) Adds an item to the rear of the Queue.
dequeue() Removes and returns the front item.
front() Returns the front item without removing it.
isEmpty() Checks whether the Queue contains no items.
Real-Life Example

A line of people waiting at a ticket counter behaves like a Queue: the person who arrives first is served first.

More Examples

Common Abstract Data Types

Many familiar data types can be described by their behavior and supported operations.

List

Represents an ordered collection of elements.

add() remove() get()

Set

Represents a collection of unique elements.

add() contains() remove()

Map

Associates keys with corresponding values.

put() get() remove()

Priority Queue

Processes elements according to priority rather than only their arrival order.

insert() peek() remove()
Benefits

Why Are ADTs Important?

ADTs help developers design software around clear behavior instead of depending on implementation details.

Abstraction

You can use operations without needing to understand their internal implementation.

Easier Maintenance

An implementation can be changed without changing how users interact with the ADT, as long as its behavior remains the same.

Reusability

The same abstract behavior can be implemented and reused in different programs.

Clear Design

Defining operations and rules makes software easier to understand, test, and maintain.

Summary

Key Takeaways

Review the most important ideas before moving to the next lesson.

An Abstract Data Type (ADT) defines behavior and supported operations.

A data structure determines how data is organized and how operations are implemented.

A Stack follows LIFO, while a Queue follows FIFO.

The same ADT behavior can often be implemented using different data structures.

Quick Reminder

ADT = What operations are available? Data Structure = How are those operations implemented?
