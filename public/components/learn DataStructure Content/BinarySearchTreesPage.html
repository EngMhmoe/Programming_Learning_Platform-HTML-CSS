Binary Search Trees (BST)

Learn how Binary Search Trees organize values, how searching and insertion work, how nodes are deleted, and why tree balance affects performance.

Previous Next
Definition

What Is a Binary Search Tree?

A Binary Search Tree (BST) is a binary tree that organizes values according to a comparison rule. For each node, values in the left subtree are smaller, while values in the right subtree are larger, assuming unique keys.

Ordered for Efficient Searching

At each node, compare the target with the current value. Move left when the target is smaller and right when it is larger. This ordering helps eliminate part of the tree during a search.

Remember

Every Binary Search Tree is a binary tree, but not every binary tree follows the BST ordering rule.

Core Rules

Binary Search Tree Properties

The BST ordering rule applies to every node and to every subtree, not only to the root.

Left Subtree

Values in the left subtree are smaller than the current node's value.

Right Subtree

Values in the right subtree are larger than the current node's value.

Recursive Rule

Both the left and right subtrees must independently satisfy the BST property.

What About Duplicate Values?

Duplicate handling depends on the implementation. A BST may reject duplicates, count their occurrences, or define a consistent placement rule.

Operation 01

Searching in a Binary Search Tree

Searching starts at the root and compares the target value with each visited node.

Key Idea

You do not need to visit every node. Each comparison tells you which subtree may contain the target.

Operation 02

Inserting a New Node

Insertion follows the same comparisons used during searching until an empty child position is found.

01

Start at the Root

Compare the new value with the current node.

02

Choose a Direction

Move left if the value is smaller, or right if it is larger.

03

Insert the Node

When the selected child position is empty, insert the new node there.

Insertion Example Pseudocode 
function insert(node, value):
    if node is null:
        return new Node(value)

    if value < node.value:
        node.left = insert(node.left, value)
    else if value > node.value:
        node.right = insert(node.right, value)

    return node
Note

This pseudocode ignores duplicate values. An actual implementation should define how duplicates are handled.

Operation 03

Deleting a Node

Deletion has three common cases. The correct approach depends on the number of children the target node has.

Case 01

Leaf Node

A leaf has no children. Remove it directly from its parent.

Remove 20

Case 02

One Child

Replace the node with its only child so the remaining subtree stays connected.

Remove 20 and connect 30 to 10

Case 03

Two Children

Replace the node's value with its inorder successor or predecessor, then remove that replacement node from its original position.

Example replacement using successor 60

Important

The inorder successor is the smallest value in the node's right subtree. Reconnecting nodes correctly preserves the BST property.

Traversal

Traversing a Binary Search Tree

Tree traversal visits nodes in a particular order. Inorder traversal is especially useful for BSTs because it visits values in sorted order.

Inorder: Left → Root → Right

Visits the left subtree, current node, and right subtree.

20 30 40 50 60 70 80

Preorder: Root → Left → Right

Visits the current node before its left and right subtrees.

Postorder: Left → Right → Root

Visits both subtrees before visiting the current node.

Remember

For a BST containing unique values, inorder traversal produces the values in ascending order.

Performance

Binary Search Tree Time Complexity

Search, insertion, and deletion depend on the height of the tree.

Operation Average Case Worst Case
Search O(log n) O(n)
Insertion O(log n) O(n)
Deletion O(log n) O(n)
Traversal O(n) O(n)
O(log n)

Balanced Tree

A balanced tree has a height proportional to log n, allowing efficient operations.

O(n)

Skewed Tree

A badly unbalanced tree can behave like a linked list, requiring many comparisons.

Do Not Confuse the Cases

A regular BST does not guarantee O(log n) operations. Self-balancing trees, such as AVL trees and Red-Black trees, maintain logarithmic height.

Key Difference

Binary Tree vs Binary Search Tree

Both structures allow each node to have at most two children, but their ordering rules differ.

Binary Tree

Structure

Each node can have up to two children. The values do not have to follow a particular ordering rule.

Binary Search Tree

Structure + Ordering

Each node can have up to two children, and values must follow the BST ordering rule throughout the tree.

Applications

Where Are Binary Search Trees Used?

BSTs are useful when data needs to be searched and maintained in an ordered form.

Searching Data

Locate values through comparisons rather than scanning every element in a suitable tree.

Ordered Data

Maintain values in an order that supports sorted traversal and range queries.

Dynamic Collections

Insert and remove values while maintaining an ordered tree structure.

Summary

Key Takeaways

Review the most important Binary Search Tree concepts before moving to the next lesson.

A Binary Search Tree is a binary tree that follows an ordering rule.

Smaller values are placed in the left subtree and larger values in the right subtree, under the unique-key rule.

Searching and insertion follow comparisons from the root toward a child.

Deletion has three cases: a leaf, a node with one child, and a node with two children.

Inorder traversal of a BST with unique keys visits values in ascending order.

BST search, insertion, and deletion can take O(n) in the worst case if the tree becomes skewed.

Quick Reminder

A BST's performance depends on its height. Keeping the tree balanced helps maintain efficient operations.
