Graphs

Learn how graphs represent relationships between objects, explore their main types, and understand how graph traversal algorithms visit vertices.

Introduction

Introduction to Graphs

A graph is a non-linear data structure used to represent relationships between objects.

What Is a Graph?

A graph consists of a set of vertices (also called nodes) and a set of edges that connect pairs of vertices. Graphs are useful when relationships are more complex than a simple linear sequence or hierarchy.

In this example, each circle represents a vertex, and each line represents an edge.

Understanding the Example

  • The graph contains four vertices: A, B, C, and D.
  • Each line represents a connection between two vertices.
  • A vertex can connect to multiple other vertices.
  • The connections do not have to form a straight line or a tree.
02
Core Concepts

Graph Terminology

Understanding the basic terminology makes graph structures and algorithms easier to learn.

Vertex

A vertex, or node, represents an individual object or entity in a graph.

Example: A, B, C, or D.

Edge

An edge represents a connection between two vertices.

Example: A connection between A and B.

Adjacent Vertices

Two vertices are adjacent when an edge directly connects them.

Example: A and B are adjacent.

Degree

In an undirected graph, the degree of a vertex is the number of edges connected to it.

Example: A vertex with three connections has degree 3.

Path

A path is a sequence of vertices connected through edges.

Example: A → B → D.

Cycle

A cycle is a path that starts and ends at the same vertex, following connected edges.

Example: A → B → C → A.
03
Graph Categories

Types of Graphs

Graphs can be classified according to the direction of their edges and whether their edges have weights.

Undirected Graph

Edges do not have a direction. A connection between A and B can be followed in either direction.

A — B
  • Connections are bidirectional.
  • Useful for representing mutual relationships.

Directed Graph

Edges have a direction, usually shown with arrows. A connection from A to B does not automatically imply a connection from B to A.

A → B
  • Connections follow a specific direction.
  • Useful for representing one-way relationships.

Weighted Graph

Each edge has an associated value called a weight. The weight can represent distance, cost, or time.

A — 5 — B
  • Edges carry numerical values.
  • Useful for route and cost calculations.

Unweighted Graph

Edges do not have explicit weights. Each connection is treated equally when considering the graph's basic structure.

A — B — C
  • Connections have no assigned edge weights.
  • Useful for simple relationship networks.

Important Note

These categories are not mutually exclusive. For example, a graph can be both directed and weighted.

04
Traversal Algorithms

Graph Traversal

Graph traversal is the process of visiting vertices in a graph. Two common traversal algorithms are BFS and DFS.

Breadth-First Search (BFS)

Level by level

BFS visits neighboring vertices first before moving farther away from the starting vertex. It commonly uses a queue to manage the next vertices to visit.

How It Works

  1. Choose a starting vertex.
  2. Visit the starting vertex and add it to a queue.
  3. Remove a vertex from the queue.
  4. Add its unvisited neighbors to the queue.
  5. Repeat until the queue is empty.
Time Complexity O(V + E)
Common Use Shortest paths in unweighted graphs

Depth-First Search (DFS)

Explore deeply

DFS explores one path as far as possible before backtracking. It can be implemented using recursion or an explicit stack.

How It Works

  1. Choose a starting vertex.
  2. Visit the vertex and mark it as visited.
  3. Move to an unvisited neighboring vertex.
  4. Continue until no unvisited neighbor remains.
  5. Backtrack and explore other paths.
Time Complexity O(V + E)
Common Use Cycle detection and connectivity analysis

What Do V and E Mean?

In the complexity expression O(V + E), V represents the number of vertices and E represents the number of edges. With an adjacency-list representation, BFS and DFS generally run in O(V + E) time.

05
Real-World Uses

Applications of Graphs

Graphs are used whenever a system contains objects and relationships between them.

Navigation Systems

Locations can be represented as vertices, while roads are edges. Weights can represent distance or travel time.

Social Networks

Users can be represented as vertices, and friendships or follows can be represented as edges.

Computer Networks

Devices can be represented as vertices and network connections as edges.

Dependency Systems

Directed graphs can model dependencies between tasks, modules, or software packages.

Search and Recommendation

Graph relationships can help systems explore connections between users, products, and content.

Project Planning

Tasks and their dependencies can be modeled using directed graphs to understand execution order.

07
Summary

Key Takeaways

Review the most important concepts before moving to graph representations.

  • A graph consists of vertices and edges that represent objects and their relationships.
  • Edges can be directed or undirected, and they may have weights.
  • Vertices can be adjacent, connected by paths, or part of cycles.
  • BFS explores neighbors level by level and commonly uses a queue.
  • DFS explores deeply before backtracking and commonly uses a stack or recursion.
  • Graphs are used in navigation, social networks, computer networks, and dependency systems.
Learning Note

Before moving on, make sure you can distinguish vertices from edges and explain the difference between BFS and DFS. These concepts will help you understand how graphs are stored and processed.
