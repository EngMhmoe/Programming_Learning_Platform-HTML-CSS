Big O Notation

Learn how Big O Notation describes algorithm efficiency, understand common growth rates, and analyze how algorithms behave as their input size increases.

Previous Next
Definition

What Is Big O Notation?

Big O Notation is a mathematical way to describe how an algorithm's resource requirements grow as the input size increases.

It is commonly used to analyze an algorithm's Time Complexity and can also describe its Space Complexity.

In Simple Words

Big O helps us understand what happens when an algorithm receives more and more data.

Instead of measuring the exact running time, we focus on how the amount of work grows as the input becomes larger.

Important

Big O does not tell us the exact number of seconds an algorithm needs. It describes how its resource usage grows with input size.

Importance

Why Does Big O Notation Matter?

Two algorithms may solve the same problem but behave very differently when the input becomes large.

Understand Efficiency

Helps estimate how the amount of work grows as the number of input elements increases.

Compare Algorithms

Makes it easier to compare different solutions without depending only on a particular computer.

Handle Large Inputs

Helps identify algorithms that may become inefficient when processing large datasets.

Input Size

Understanding Input Size (n)

In algorithm analysis, n usually represents the number of elements in the input.

Example: An Array
10 20 30 40

This array contains four elements, so n = 4.

n = 4 4 elements
n = 10 10 elements
n = 100 100 elements

An algorithm may perform a fixed amount of work, process every element once, or repeat work for combinations of elements. Big O describes how this work grows as n increases.

Complexity Types

Common Big O Complexities

These are common growth rates used to describe algorithm efficiency.

O(1) Constant

Constant Time

The number of operations stays constant as the input size grows.

Example: Accessing an array element by its index.

O(log n) Logarithmic

Logarithmic Time

The amount of work grows slowly because the problem size is repeatedly reduced.

Example: Binary Search in a sorted array.

O(n) Linear

Linear Time

The amount of work grows proportionally to the number of input elements.

Example: Looping through an array once.

O(n log n) Linearithmic

Linearithmic Time

The work grows approximately with n multiplied by log n.

Example: Merge Sort.

O(n²) Quadratic

Quadratic Time

The amount of work may grow with the square of the input size.

Example: Comparing every pair of elements using two nested loops.

O(2ⁿ) Exponential

Exponential Time

The amount of work can approximately double whenever the input size increases by one.

Example: A naive recursive solution for some combinatorial problems.

Remember

These examples describe typical patterns, not every possible implementation. Always analyze the actual algorithm to determine its complexity.

Code Example

Example 1: Constant Time — O(1)

Accessing an element by index in a typical array takes a constant amount of time.

JavaScript O(1) 
function getFirstElement(items) {
    return items[0];
}

Why O(1)?

  • The function accesses one specific array position.
  • It does not need to visit every element.
  • The number of operations stays constant as the array grows.
Code Example

Example 2: Linear Time — O(n)

Consider a function that prints every element in an array.

JavaScript O(n) 
function printItems(items) {
    for (let i = 0; i < items.length; i++) {
        console.log(items[i]);
    }
}

Why O(n)?

  • The loop visits each element once.
  • An array with 10 elements requires 10 loop iterations.
  • An array with 1,000 elements requires 1,000 loop iterations.
  • The amount of work grows linearly with n.
Code Example

Example 3: Quadratic Time — O(n²)

When a loop runs inside another loop, the total number of iterations may grow quadratically.

JavaScript O(n²) 
function printPairs(items) {
    for (let i = 0; i < items.length; i++) {
        for (let j = 0; j < items.length; j++) {
            console.log(items[i], items[j]);
        }
    }
}

Why O(n²)?

  • The outer loop runs n times.
  • For every outer iteration, the inner loop runs n times.
  • The total number of iterations is n × n = n².
  • For n = 10, the nested loops perform 100 iterations.
Code Example

Example 4: Logarithmic Time — O(log n)

Binary Search repeatedly halves the search range in a sorted array.

JavaScript O(log n) 
function binarySearch(items, target) {
    let left = 0;
    let right = items.length - 1;

    while (left <= right) {
        const middle = Math.floor((left + right) / 2);

        if (items[middle] === target) {
            return middle;
        }

        if (items[middle] < target) {
            left = middle + 1;
        } else {
            right = middle - 1;
        }
    }

    return -1;
}

Why O(log n)?

  • Each iteration eliminates approximately half of the remaining elements.
  • The algorithm does not need to inspect every element.
  • The input must be sorted for this Binary Search implementation to work correctly.
Analysis Rules

Basic Rules of Big O Notation

These rules help simplify an algorithm's complexity without counting every operation.

1

Ignore Constant Factors

Big O focuses on the growth rate, so constant multipliers are ignored.

Example O(2n) → O(n)
2

Keep the Dominant Term

When an expression contains multiple growth terms, the fastest-growing term determines the Big O classification.

Example O(n² + n) → O(n²)
3

Add Sequential Operations

For operations that run one after another, add their costs and simplify the result.

Example O(n) + O(n) → O(n)
4

Multiply Nested Loop Costs

When one loop runs n times and another loop inside it also runs n times, their combined work is proportional to n².

Example O(n) × O(n) → O(n²)
Important Note

These are useful introductory rules. More advanced algorithms may require a detailed analysis of loops, recursion, branching, and input characteristics.

Growth Comparison

How Do Growth Rates Compare?

The following table shows representative values for common growth functions as n increases.

Input (n) O(1) O(log₂ n) O(n) O(n²)
8 1 3 8 64
16 1 4 16 256
32 1 5 32 1,024
100 1 ≈ 6.64 100 10,000

These are mathematical growth-function values, not exact execution times or guaranteed operation counts for every algorithm.

What Should You Notice?

Constant and logarithmic growth increase slowly. Linear growth follows the input size, while quadratic growth increases much more rapidly.

Comparison

Big O Notation and Space Complexity

Big O is a notation that can describe different resource requirements. Time Complexity and Space Complexity are two common applications of it.

Time Complexity

Describes how the amount of work performed by an algorithm grows with the input size.

Example: O(n) time

Space Complexity

Describes how memory requirements grow with the input size.

Example: O(n) auxiliary space
Summary

Key Takeaways

  • Big O describes how an algorithm's resource requirements grow as the input size increases.
  • O(1) represents constant growth, while O(log n) represents logarithmic growth.
  • O(n) represents linear growth, and O(n²) represents quadratic growth.
  • Binary Search is a common example of an O(log n) algorithm when the input is sorted.
  • Nested loops can produce quadratic complexity, depending on their iteration counts.
  • Ignore constant factors and keep the dominant term when simplifying common Big O expressions.
  • Big O can describe both Time Complexity and Space Complexity.
