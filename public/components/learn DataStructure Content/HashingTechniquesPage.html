Hashing Techniques

Learn how hash functions map keys to table indexes, how collisions happen, and how techniques such as separate chaining and open addressing resolve them.

Previous Next
Definition

What Is Hashing?

Hashing is a technique that transforms a key into a value used to determine where the key-value pair should be stored in a hash table.

From Key to Table Index

A hash function processes a key and produces a hash value. A hash table uses that result to determine a suitable storage index.

Input "apple"
Hash Function hash(key)
Index 3
Remember

A hash function does not guarantee a unique result for every possible key. Different keys can map to the same table index, causing a collision.

Hash Function

How Does a Hash Function Work?

A hash function converts a key into a hash value. The implementation then maps that value to an index within the available table capacity.

01

Receive the Key

Start with the value you want to store or find.

"apple"
02

Calculate the Hash

Apply the hash function to the key.

hash("apple")
03

Find the Index

Map the hash value to a valid table position.

hash % capacity
Important

The expression hash % capacity is a common way to map a non-negative hash value to a table index. Real implementations may use different index-mapping strategies.

Good Design

Properties of a Good Hash Function

A good hash function helps a hash table distribute keys effectively and reduce collisions.

Fast to Compute

The function should calculate hash values efficiently for frequent operations.

Uniform Distribution

Keys should be spread across the table rather than concentrated in a small number of indexes.

Consistent Results

The same key should produce the same hash result when evaluated under the same rules.

Low Collision Rate

Different keys should be distributed in a way that reduces frequent collisions.

Keep in Mind

No finite hash table can assign a unique index to every possible key. A good hash function reduces collisions but cannot eliminate them in every situation.

Collision

What Is a Hash Collision?

A collision occurs when two different keys map to the same index in a hash table.

Key A "apple"
Key B "grape"
Hash Function
Same Index: 3 Collision detected

The hash table must use a collision-resolution technique to store both entries without losing their values.

Why Collisions Happen

The set of possible keys is usually much larger than the number of available table indexes. Multiple keys can therefore map to the same index.

Technique 01

Separate Chaining

Separate chaining stores multiple entries that map to the same index in a collection associated with that table position, commonly a linked list.

How It Works

  • Each table index points to a collection of entries.
  • Colliding keys are stored in the same collection.
  • The collection can be traversed to find a key.
Index 3
"apple"
"grape"
NULL

Advantage: Chaining can store multiple colliding entries without searching for another empty table slot.

Technique 02

Open Addressing

Open addressing stores all entries directly inside the table. When a collision occurs, the algorithm probes other positions until it finds a suitable slot.

Example: Linear Probing

Find the Next Available Slot

If the target index is occupied, check the next index, continuing through the table according to the probing rule.

Index 0 "kiwi"
Index 1 "apple"
Index 2 "grape"
Index 3 "orange" Inserted here
Index 4 Empty

Important: Open addressing requires careful handling of insertion, lookup, deletion, and table load factor.

Probing Methods

Types of Open Addressing

Open addressing uses different probing strategies to search for an available position after a collision.

Linear Probing

Checks consecutive positions until an available slot is found.

(h(key) + i) % capacity
Example: 3 → 4 → 5

Quadratic Probing

Uses squared offsets to determine the next positions to inspect.

(h(key) + c1i + c2i²) % capacity
Example: 3 → 4 → 7

Double Hashing

Uses a second hash function to determine the step size between probes.

(h1(key) + i × h2(key)) % capacity
Step size depends on the second hash
Choosing a Probing Strategy

Linear probing is simple but can create clusters of occupied positions. Quadratic probing changes the step pattern, while double hashing uses a second hash function to vary the step size.

Comparison

Chaining vs Open Addressing

Both approaches resolve collisions, but they organize entries differently.

Feature Separate Chaining Open Addressing
Storage Entries stored in collections per index Entries stored directly in table slots
Collision Handling Add entry to the same collection Probe another table position
Extra Memory May need extra nodes or collections Usually avoids separate chain nodes
Load Factor Can exceed 1 Must remain below 1 for an empty slot to exist
Load Factor

Load factor is commonly defined as the number of stored entries divided by the table capacity. Its effect on performance depends on the collision strategy and implementation.

Performance

Hashing Time Complexity

Hash tables usually provide fast average-case operations, but collisions can increase the amount of work required.

Lookup O(1) Average

Usually accesses the desired entry quickly.

Insertion O(1) Average

Usually inserts an entry with a small number of probes or collection operations.

Worst Case O(n) Lookup / Update

Many collisions can require examining a large number of entries or slots.

Complexity Note

Average O(1) is the typical target for a well-designed hash table. Worst-case behavior can be O(n), depending on collisions and the implementation.

Evaluation

Benefits and Limitations

Hashing is useful for fast key-based access, but its performance depends on the function, table capacity, and collision-resolution strategy.

Benefits

  • Fast average lookup, insertion, and deletion.
  • Useful for dictionaries, caches, and indexes.
  • Efficient access through keys.
  • Multiple collision strategies are available.

Limitations

  • Collisions cannot always be avoided.
  • Poor hash functions can reduce performance.
  • Resizing may require rebuilding table entries.
  • Hash tables are not designed for sorted traversal.
Summary

Key Takeaways

Review the main hashing concepts before continuing to the next data structure.

A hash function maps a key to a hash value used to determine a table index.

A collision occurs when different keys map to the same table index.

Separate chaining stores colliding entries in a collection associated with the same index.

Open addressing resolves collisions by probing other positions in the table.

Good hash functions distribute keys effectively, improving average-case performance.

Quick Reminder

Hash function → Table index → Collision handling when two keys map to the same position.
