Time Complexity

Understand how to analyze the running time of an algorithm, compare different solutions, and estimate how performance changes as the input size grows.

Definition

What Is Time Complexity?

Time Complexity describes how the number of operations performed by an algorithm grows as the input size increases.

Measure Growth, Not Just Seconds

Instead of measuring only the actual time in seconds, we study how an algorithm's work changes when it receives more data. This helps us compare algorithms independently of a particular computer.

Important

Time Complexity is not an exact stopwatch measurement. It describes how computational work grows as the input size grows.

Importance

Why Does Time Complexity Matter?

Two algorithms may solve the same problem, but their performance can be very different when the input becomes large.

Imagine Searching for a Name

You have a list containing thousands of names and need to find one person.

Check One by One

You may need to inspect many names before finding the correct one.

Linear Search: O(n)

Repeatedly Halve a Sorted List

If the list is sorted, Binary Search can eliminate half of the remaining candidates at each step.

Binary Search: O(log n)

In complexity analysis, the letter n commonly represents the size of the input processed by an algorithm.

Remember

The input size depends on the problem. For an array, n usually means the number of elements. For a graph, it may involve the number of vertices and edges.

Big O Notation

What Is Big O Notation?

Big O notation describes an upper bound on how an algorithm's running time grows with input size. It helps us discuss performance without focusing on machine-specific timing details.

O

Focus on the Growth Rate

When analyzing an algorithm, we usually focus on the dominant growth term and ignore constant factors and lower-order terms.

Example: 3n + 5 → O(n)
1

Ignore Constant Factors

5n and 100n both have linear growth, so both are described as O(n).

2

Keep the Dominant Term

n² + n + 10 is described as O(n²) because the quadratic term dominates for large n.

3

Consider Large Inputs

Big O is especially useful for understanding how an algorithm scales as input size grows.

Common Time Complexities

Logarithmic Time

Linear Time

Example Simple Loop
04 Good for Sorting

Linearithmic Time

O(n log n)

The work combines linear processing with logarithmic levels of computation.

Example Merge Sort
05 Slower Growth

Quadratic Time

O(n²)

The work often grows with the square of the input size.

Example Nested Loops
06 Very Expensive

Exponential Time

O(2ⁿ)

The amount of work can approximately double with each additional input element.

Example Some Recursive Algorithms
A Useful Rule of Thumb

For large inputs, constant and logarithmic growth are generally more scalable than quadratic or exponential growth. The actual performance also depends on the algorithm and its assumptions.

Code Examples

Analyze Simple Code

Let's connect the notation to simple code examples.

Example 01 O(1)

Constant Time

Accessing an element at a known array index takes constant time under the usual array model. 

function getFirst(arr) {
    return arr[0];
}

The function performs a fixed number of operations, regardless of how many elements the array contains.

Example 02 O(n)

Linear Time

This loop visits every element in the array once. 

function printAll(arr) {
    for (let i = 0; i < arr.length; i++) {
        console.log(arr[i]);
    }
}

If the array contains n elements, the loop processes n elements. More elements mean proportionally more work.

Example 03 O(n²)

Quadratic Time

The inner loop runs for each iteration of the outer loop. 

function printPairs(arr) {
    for (let i = 0; i < arr.length; i++) {
        for (let j = 0; j < arr.length; j++) {
            console.log(arr[i], arr[j]);
        }
    }
}

For n elements, the nested loops perform approximately n × n iterations, giving quadratic growth.

Cases

Best, Average, and Worst Cases

An algorithm can perform a different amount of work depending on the input it receives.

Best Case

The most favorable input situation for the algorithm.

Example: Finding the target as the first element in a linear search.

Average Case

The expected work across inputs under a specified input distribution.

Example: A target is equally likely to appear at any position in a list.

Worst Case

The maximum work required for any input of a given size.

Example: The target is at the last position or is not present in a linear search.
Important Distinction

Best, average, and worst cases describe different input scenarios. Big O is a mathematical growth bound and is often used to express worst-case complexity, but it is not limited to worst-case analysis.

Summary

Key Takeaways

Review the most important ideas before moving to the next lesson.

Time Complexity describes how computational work grows with the input size.

The variable n commonly represents the input size.

Big O notation describes an upper bound on growth and helps compare algorithms.

Common complexities include O(1), O(log n), O(n), O(n log n), and O(n²).

Nested loops often lead to quadratic time when both loops iterate over n elements.
