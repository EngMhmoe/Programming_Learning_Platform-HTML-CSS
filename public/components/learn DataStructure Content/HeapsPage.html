Heaps in Data Structure

Learn how Heaps organize data, understand Min-Heaps and Max-Heaps, and explore heap operations and their time complexity.

Previous Next
01

Introduction to Heaps

Understand the structure and purpose of a Heap.

What Is a Heap?

A Heap is a specialized tree-based data structure that satisfies a specific ordering rule called the Heap Property. It is commonly implemented using an array and is useful when we need quick access to the smallest or largest element.

Key Idea

In a Heap, the root contains the highest-priority element: the minimum element in a Min-Heap or the maximum element in a Max-Heap.

Important Note

A Heap is not the same as a Binary Search Tree. A Heap maintains a parent-child ordering rule, but its left and right subtrees are not necessarily sorted.

02

Heap Properties

The two important rules that define a Binary Heap.

Shape Property

A Binary Heap is a Complete Binary Tree. Every level is completely filled except possibly the last, which is filled from left to right.

Heap Property

Every parent follows the ordering rule of its children. In a Min-Heap, the parent is smaller than or equal to its children. In a Max-Heap, the parent is greater than or equal to its children.

Example of a Min-Heap

Each parent is smaller than or equal to its children.

10
20
15
40
50

35

The root contains the smallest value: 10.

03

Types of Heaps

Compare Min-Heaps and Max-Heaps.

Min-Heap

The value of every parent node is less than or equal to the values of its children.

Root Smallest value
  • Quick access to the minimum element.
  • Useful for priority queues and scheduling.

Max-Heap

The value of every parent node is greater than or equal to the values of its children.

Root Largest value
  • Quick access to the maximum element.
  • Useful for highest-priority item selection.

Neither type requires all values in the tree to be sorted. The ordering rule applies between each parent and its children.

04

Array Representation

A Binary Heap can be stored efficiently in an array.

Because a Binary Heap is a Complete Binary Tree, its nodes can be stored level by level in an array without needing pointers for left and right children.

Example Array

0 10
1 20
2 15
3 40
4 50
5 30
6 35

The array stores the nodes level by level, from left to right.

Index Formulas

For a zero-based array, the relationships between a node and its children can be calculated using its index.

Parent Math.floor((i - 1) / 2)
Left Child 2 * i + 1
Right Child 2 * i + 2
Remember

These formulas assume the array starts at index 0. If a node is at index i, its left and right children can be located directly using the formulas above.

05

Common Heap Operations

Understand how a Heap is maintained when its data changes.

Insert

Add the new element at the end of the array, then move it upward until the Heap Property is restored. This process is often called sift-up or heapify-up.

O(log n)

Extract Root

Remove the root, move the last element to the root, and move it downward until the Heap Property is restored.

O(log n)

Peek

Read the root element without removing it. It gives direct access to the minimum in a Min-Heap or the maximum in a Max-Heap.

O(1)

Build Heap

Convert an unordered array into a Heap using the bottom-up heap construction algorithm.

O(n)

The time complexities shown are for a standard Binary Heap. Searching for an arbitrary value is generally O(n), because a Heap does not keep all values fully sorted.

07

Key Takeaways

The most important points to remember about Heaps.

  • A Binary Heap is a Complete Binary Tree.
  • A Min-Heap keeps the smallest value at the root.
  • A Max-Heap keeps the largest value at the root.
  • A Binary Heap is commonly stored in an array.
  • Insertion and root extraction take O(log n) time.
  • Reading the root takes O(1) time.
