Space Complexity

Learn how to measure the memory an algorithm uses, understand auxiliary space, and compare algorithms based on their memory requirements.

Previous Next
Definition

What Is Space Complexity?

Space Complexity describes how much memory an algorithm needs while it runs, in relation to the size of its input.

An algorithm may need memory to store input data, create variables, build additional data structures, or perform recursive function calls.

In Simple Words

Time Complexity asks: How does the running time grow?

Space Complexity asks: How does the memory usage grow?

Important

Space Complexity describes how memory usage grows as the input size grows. It is not simply the amount of memory used at one particular moment.

Importance

Why Does Space Complexity Matter?

An algorithm should not only run efficiently. It should also use memory wisely.

Memory Efficiency

Helps avoid unnecessary memory usage when processing large amounts of data.

Limited Devices

Matters on devices and systems with limited available memory.

Algorithm Comparison

Helps compare solutions that perform the same task but require different amounts of extra memory.

Input Size

What Does n Mean?

In complexity analysis, the letter n usually represents the size of the input.

Example: An Array
10 20 30 40

This array contains 4 elements, so n = 4.

n = 4 4 elements
n = 8 8 elements
n = 100 100 elements

When the input grows, the memory required by an algorithm may stay constant or grow with the input. Space Complexity helps describe that growth.

Key Concepts

Total Space vs. Auxiliary Space

Space analysis commonly distinguishes between the memory needed for the input and the extra memory created by the algorithm.

Total Space

Total Memory

Includes the memory used for the input and the additional memory required during execution, depending on the analysis.

Auxiliary Space

Extra Memory

Refers to the additional memory an algorithm uses beyond the input storage itself.

Remember

In many algorithm problems, when someone asks for space complexity, they are mainly interested in auxiliary space. Always check how the problem defines the input memory.

Complexity Types

Common Space Complexities

These notations describe how the additional memory may grow as the input size increases.

O(1) Constant

Constant Space

Uses a fixed amount of additional memory, regardless of the input size.

Example: Using a fixed number of variables.

O(log n) Logarithmic

Logarithmic Space

Memory grows logarithmically with the input size.

Example: The recursion stack in some divide-and-conquer algorithms.

O(n) Linear

Linear Space

Memory grows proportionally to the input size.

Example: Creating a new array containing n elements.

O(n²) Quadratic

Quadratic Space

Memory grows proportionally to the square of the input size.

Example: A two-dimensional n × n matrix.

Important Note

These are common growth patterns, not a ranking that applies to every implementation. The actual space complexity depends on the algorithm and its data structures.

Code Example

Example 1: Constant Space — O(1)

Consider a function that adds two numbers and stores the result in one variable.

JavaScript O(1) Space 
function addNumbers(a, b) {
    const result = a + b;
    return result;
}

Why O(1)?

  • The function uses a fixed number of parameters and a local variable.
  • It does not create a collection that grows with the input.
  • The additional memory remains constant as the input values change.
Code Example

Example 2: Linear Space — O(n)

Now consider a function that creates a new array containing every element from the input array.

JavaScript O(n) Space 
function copyArray(items) {
    const copiedItems = [];

    for (let i = 0; i < items.length; i++) {
        copiedItems.push(items[i]);
    }

    return copiedItems;
}

Why O(n)?

  • The new array stores a copy of each input element.
  • If the input has 10 elements, the new array stores 10 elements.
  • If the input has 1,000 elements, the new array stores 1,000 elements.
  • The extra memory grows with the input size.
Code Example

Example 3: Quadratic Space — O(n²)

A two-dimensional matrix with n rows and n columns stores n × n elements.

JavaScript O(n²) Space 
function createMatrix(n) {
    const matrix = [];

    for (let row = 0; row < n; row++) {
        matrix[row] = [];

        for (let col = 0; col < n; col++) {
            matrix[row][col] = 0;
        }
    }

    return matrix;
}

Why O(n²)?

  • The matrix has n rows.
  • Each row contains n elements.
  • The total number of stored elements is n × n = n².
  • For n = 4, the matrix stores 16 elements.
  • For n = 10, the matrix stores 100 elements.
Recursion

How Does Recursion Affect Space Complexity?

Every active recursive function call needs space for its execution state. These calls are tracked using the call stack.

Recursive Countdown 
function countdown(n) {
    if (n <= 0) {
        return;
    }

    countdown(n - 1);
}
countdown(3)
countdown(2)
countdown(1)
countdown(0)

This countdown creates up to a number of active calls proportional to n, so its call-stack space is O(n).

Remember

Recursive algorithms do not all have the same space complexity. It depends on how many calls remain active at the same time and how much memory each call needs.

Comparison

Time Complexity vs. Space Complexity

Point Time Complexity Space Complexity
Measures How running time grows How memory usage grows
Main Question How much work is needed? How much memory is needed?
Example Loop through n elements: O(n) Create an array of n elements: O(n)
Goal Reduce unnecessary work Reduce unnecessary memory usage

An algorithm may be fast but use a lot of memory, or use little memory but perform more work. Good algorithm design considers both.

Summary

Key Takeaways

  • Space Complexity describes how memory requirements grow with input size.
  • Auxiliary Space means extra memory used by an algorithm beyond input storage.
  • O(1) represents constant additional space.
  • O(n) represents memory that grows linearly with the input size.
  • O(n²) can describe a square matrix with n rows and n columns.
  • Recursive calls can use additional memory on the call stack.
  • Efficient algorithms should consider both Time Complexity and Space Complexity.
