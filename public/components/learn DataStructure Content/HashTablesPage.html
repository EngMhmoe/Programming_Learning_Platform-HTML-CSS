Data Structure Programming

Hash Tables

Learn how Hash Tables store key-value pairs, use hash functions to find locations, handle collisions, and support efficient insertion, searching, and deletion.

Previous Next
Definition

What Is a Hash Table?

A Hash Table is a data structure that stores data as key-value pairs. It uses a hash function to calculate an index where an item should be stored or searched for.

Find Data Using a Key

Instead of searching every item one by one, a Hash Table uses a key to calculate a location and access the associated value.

Key Hash Function Index
Remember

A Hash Table does not usually search by checking every item. It calculates a likely storage location from the key, although collisions can require additional work.

Main Concept

How Does a Hash Table Work?

A hash function converts a key into an index. The index helps determine where the corresponding value will be stored in the table.

Step 01

Provide a Key

Start with the key used to store or retrieve a value.

"apple"
Step 02

Calculate a Hash

The hash function processes the key and calculates an index.

hash(key)
Step 03

Access the Index

Use the calculated index to locate the corresponding entry.

table[index]

The same key should produce the same hash result when the hash function and table configuration remain unchanged.

Core Concept

Key-Value Pairs

A Hash Table stores an association between a key and its corresponding value. The key is used to find the value efficiently.

Lookup by Key

A key provides a way to find its associated value without scanning every entry in the average case.

Update a Value

When a key already exists, its associated value can usually be updated.

Remove an Entry

An entry can be removed by identifying its key and locating the associated record.

Hash Function

What Is a Hash Function?

A hash function takes a key and produces a hash value. A Hash Table uses that result to determine a valid position in its storage structure.

Example Formula

Modulo-Based Hash Function

hash(key) = key % tableSize

For a simple example using integer keys, the remainder operator can map a key to an index within the table's range.

Key 27
Table Size 10
Calculation 27 % 10 = 7
Resulting Index 7
Keep in Mind

This modulo formula is a simplified example for integer keys. Hash functions for strings and other key types require different logic.

Operations

Basic Hash Table Operations

Hash Tables commonly support inserting entries, retrieving values, updating existing entries, removing entries, and checking whether a key exists.

Insert

set(key, value)

Adds a new key-value pair or updates the value associated with an existing key.

Search / Retrieve

get(key)

Finds the entry associated with a key and returns its value when it exists.

Delete

delete(key)

Removes the entry associated with the specified key, if it exists.

Check Existence

has(key)

Checks whether a key is present in the Hash Table.

JavaScript Example

Using the Map Object 

const fruits = new Map();

fruits.set("apple", 12);
fruits.set("banana", 8);

console.log(fruits.get("apple")); // 12

console.log(fruits.has("banana")); // true

fruits.delete("banana");

console.log(fruits.has("banana")); // false

JavaScript's Map is a built-in key-value collection. It demonstrates common map operations, but its internal implementation is not guaranteed to be a simple array-based Hash Table.

Important Challenge

What Is a Hash Collision?

A collision occurs when two different keys produce the same table index. A Hash Table must use a collision-handling strategy to store both entries.

Collision Example

Two Keys, One Index

Key A 12
Key B 22
hash(key) = key % 10
Both keys produce index 2 Collision

Both keys produce index 2 because 12 % 10 = 2 and 22 % 10 = 2.

Separate Chaining

Each table position can hold a collection of entries that map to the same index.

Index 2
12 22

Open Addressing

If a position is occupied, the algorithm searches for another available position according to a probing rule.

Index 2
12 22
Important

Collisions are normal in Hash Tables. A suitable collision-handling strategy allows different keys to be stored correctly even when their hash results match.

Performance

Hash Table Time Complexity

Hash Tables are popular because their basic operations are usually efficient when the hash function distributes keys well and collisions are managed effectively.

Insert

O(1) Average

Adding an entry usually takes constant time, excluding occasional resizing costs.

Search

O(1) Average

A well-distributed hash function often allows quick access to an entry.

Delete

O(1) Average

Removing an entry is usually constant time under typical conditions.

Worst Case

O(n)

Many collisions can make an operation examine multiple entries.

Average vs Worst Case

O(1) describes the expected average performance under suitable conditions. It is not a guarantee that every Hash Table operation always takes constant time.

Summary

Advantages and Limitations

Hash Tables provide efficient key-based access, but their performance and behavior depend on how keys are distributed and collisions are handled.

Advantages

  • Fast average insertion and lookup.
  • Convenient key-value storage.
  • Efficient deletion by key.
  • Useful for lookups and counting tasks.

Limitations

  • Collisions require extra handling.
  • Worst-case operations can take O(n).
  • Hash Tables do not inherently maintain keys in sorted order.
  • Resizing can require additional work and memory.
Key Takeaways

What Have We Learned?

Review the main concepts before moving to the next lesson.

A Hash Table stores data as key-value pairs.

A hash function calculates a hash result used to determine a table index.

A collision happens when different keys map to the same index.

Separate chaining and open addressing are two common collision-handling approaches.

Insert, search, and delete commonly have O(1) average time complexity, while their worst case can be O(n).

Quick Reminder

Key → Hash Function → Index → Entry. If multiple keys map to the same index, the Hash Table must handle the collision.
