Core Concept

What Is Big O Notation?

Big O Notation describes how an algorithm's resource requirements grow as the input size increases.

Imagine you have an algorithm that searches for a number inside an array. If the array becomes larger, the algorithm may need to perform more operations.

Big O gives us a way to describe this growth without depending on a specific computer, processor speed, or programming language.

Simple Definition

Big O describes how an algorithm's work or memory usage grows as its input gets larger.

General Representation
O(f(n))

The function f(n) represents the growth pattern of the algorithm.

O Growth notation
n Input size
f(n) Growth function
Everyday Example

Finding one specific book on a shelf of 10 books is usually easier than finding it among 1,000 books. Big O helps describe how the search effort changes as the number of books grows.

Understanding Growth

Input Size and Growth Rate

The input size is commonly represented by the letter n. It helps us describe how much work an algorithm performs.

Small Input

n = 10

10 items to process

Medium Input

n = 100

100 items to process

Large Input

n = 1,000

1,000 items to process

Why Does Growth Matter?

An algorithm that performs one operation for each item will perform approximately 10 operations for 10 items, 100 operations for 100 items, and 1,000 operations for 1,000 items.

JavaScript
O(n) 
function printItems(items) {
    for (let i = 0; i < items.length; i++) {
        console.log(items[i]);
    }
}

How It Works

  1. The function receives an array.
  2. The loop starts at index zero.
  3. Each iteration processes one item.
  4. The loop stops when all items have been processed.
Time Complexity: O(n)

The number of operations grows proportionally to the number of items.

Complexity Classes

Common Big O Complexity Classes

These are common growth patterns you will encounter when analyzing algorithms.

01 Excellent
O(1)

Constant Time

The number of operations stays approximately the same regardless of input size.

array[0]
02 Good
O(log n)

Logarithmic Time

The search space is reduced significantly at each step, as in binary search on sorted data.

Binary Search
03 Good
O(n)

Linear Time

The amount of work grows proportionally to the number of input items.

One loop
04 Moderate
O(n log n)

Linearithmic Time

Common in efficient comparison-based sorting algorithms such as merge sort.

Merge Sort
05 Slower Growth
O(n²)

Quadratic Time

Work can grow proportionally to the square of the input size, often with two nested loops.

Nested loops
06 Very Slow Growth
O(2ⁿ)

Exponential Time

The amount of work may roughly double whenever another input element is added.

Some recursive solutions
Important

These classes describe growth patterns, not exact execution times. Real performance also depends on implementation details and the input.

Compare Growth

How Complexity Grows

Compare the approximate number of operations for different complexity classes as the input size grows.

Complexity n = 10 n = 100 n = 1,000 Growth Pattern
O(1) 1 1 1 Constant
O(log n) ~3 ~7 ~10 Logarithmic
O(n) 10 100 1,000 Linear
O(n log n) ~33 ~664 ~9,966 Linearithmic
O(n²) 100 10,000 1,000,000 Quadratic
O(2ⁿ) 1,024 ~1.27 × 10³⁰ Extremely large Exponential
What Should You Notice?

Linear growth is usually much more manageable than quadratic growth for large inputs. Exponential growth can become impractical very quickly.

Values are illustrative growth estimates. Logarithmic values use base 2, and Big O does not specify exact operation counts or elapsed time.

Simplification Rules

How to Simplify Big O Expressions

When analyzing complexity, we usually focus on the dominant growth term and ignore constant factors.

01

Ignore Constant Factors

Constant multipliers do not change the overall growth class.

O(5n) → O(n)
02

Keep the Dominant Term

When a polynomial contains multiple terms, the fastest-growing term dominates for large n.

O(n² + n + 1) → O(n²)
03

Add Sequential Operations

For consecutive sections, add their work and then simplify the resulting expression.

O(n) + O(n) → O(n)
04

Multiply Nested Work

If one loop performs n iterations and each iteration runs another n-iteration loop, the total work can be quadratic.

O(n × n) → O(n²)
Remember

Simplification is about asymptotic growth. It does not mean that constants and smaller terms never affect real execution time for a particular input size.

Example 01

Constant Time — O(1)

An operation has constant time complexity when its work does not grow with the number of items in the input.

JavaScript
O(1) 
function getFirstItem(items) {
    return items[0];
}

const numbers = [10, 20, 30, 40, 50];

console.log(getFirstItem(numbers));

Step-by-Step Explanation

  1. The function receives an array.
  2. It accesses the element at index zero.
  3. It returns that element without looping through the array.
Result: 10

Accessing the first array element takes a constant number of basic operations under the usual array model, regardless of the array's length.

Why O(1)?

The function does not need to inspect every item. The number of items can increase while the basic operation count remains constant.

Example 02

Linear Time — O(n)

Linear time occurs when an algorithm's work grows proportionally to the number of input items.

JavaScript
O(n) 
function printItems(items) {
    for (let i = 0; i < items.length; i++) {
        console.log(items[i]);
    }
}

printItems([10, 20, 30, 40, 50]);

Step-by-Step Explanation

  1. The loop starts at index zero.
  2. Each iteration prints one item.
  3. For five items, the loop processes five items.
  4. If the input doubles, the loop's iterations also double.
Time Complexity: O(n)

The loop processes each item once, so its work grows linearly with the input size.

Example 03

Quadratic Time — O(n²)

Quadratic time commonly appears when an algorithm performs a full iteration inside another full iteration.

JavaScript
O(n²) 
function printPairs(items) {
    for (let i = 0; i < items.length; i++) {
        for (let j = 0; j < items.length; j++) {
            console.log(items[i], items[j]);
        }
    }
}

printPairs([1, 2, 3]);

Step-by-Step Explanation

  1. The outer loop runs n times.
  2. For every outer iteration, the inner loop also runs n times.
  3. The total number of inner-loop executions is n × n.
  4. Therefore, the time complexity is O(n²).
Time Complexity: O(n²)

With three items, the inner statement runs nine times. With ten items, it runs one hundred times.

Performance Warning

Nested loops do not always mean O(n²). You must examine how many times each loop runs and how the loops depend on the input.

Loop Analysis

Sequential Loops vs. Nested Loops

The structure of loops helps us estimate how many operations an algorithm performs.

Sequential Loops

O(n) + O(n) = O(n)
JavaScript
O(n) 
for (let i = 0; i < n; i++) {
    console.log(i);
}

for (let j = 0; j < n; j++) {
    console.log(j);
}

Each loop runs n times. Together, they perform approximately 2n iterations.

Final Complexity O(n)

Nested Loops

O(n) × O(n) = O(n²)
JavaScript
O(n²) 
for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
        console.log(i, j);
    }
}

For every outer-loop iteration, the inner loop runs n times, giving approximately n² iterations.

Final Complexity O(n²)
Key Difference

Separate loops usually add their work; fully nested loops often multiply their work. Always analyze the actual iteration counts before deciding.

Case Analysis

Best Case, Average Case, and Worst Case

An algorithm may perform different amounts of work depending on the input and where the required value appears.

JavaScript
Linear Search 
function findItem(items, target) {
    for (let i = 0; i < items.length; i++) {
        if (items[i] === target) {
            return i;
        }
    }

    return -1;
}

Best Case

O(1)

The target is the first item, so the algorithm finds it immediately.

Average Case

O(n)

The algorithm may inspect a substantial portion of the array before finding the target.

Worst Case

O(n)

The target is last or missing, so the algorithm may inspect every item.

Important Distinction

Best, average, and worst case describe different input scenarios. Big O is commonly used to express an asymptotic upper bound, and it is often used when discussing worst-case performance.

Algorithm Resources

Time Complexity vs. Space Complexity

Algorithms can be analyzed in terms of the time they require and the additional memory they use.

Time Complexity

Describes how the number of operations grows as the input size increases.

Example One loop: O(n)

Space Complexity

Describes how memory requirements grow with the input size, often focusing on auxiliary space.

Example Copying an array: O(n)

Common Mistakes

Common Big O Mistakes

Avoid these mistakes when analyzing an algorithm's complexity.

Counting Only Lines of Code

A short line inside a nested loop may execute many times. Analyze execution frequency rather than counting lines.

Keeping Every Constant

Big O simplification normally removes constant multipliers, such as reducing O(5n) to O(n).

Assuming Every Nested Loop Is O(n²)

A nested loop may have different bounds or depend on the outer loop. Inspect the actual number of iterations.

Confusing Big O With Exact Runtime

Big O describes growth, not an exact number of milliseconds. Two O(n) algorithms may still run at different speeds.

Ignoring Input Size

The meaning of complexity depends on how the algorithm's work changes as the input grows.

Lesson Summary

Key Takeaways

Review the main ideas before testing your understanding.

  • Big O describes how an algorithm's resource usage grows as its input size increases.
  • The input size is commonly represented by n.
  • O(1) is constant time, while O(n) is linear time.
  • Two fully nested loops that each run n times commonly produce O(n²) time complexity.
  • Sequential operations are added, and the final expression is simplified to its dominant term.
  • Time complexity and space complexity measure different algorithm resources.
