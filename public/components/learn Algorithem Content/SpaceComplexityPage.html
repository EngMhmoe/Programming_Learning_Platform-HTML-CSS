Space Complexity Algorithms

Learn how to measure the memory an algorithm needs, understand common space complexity classes, and analyze how memory usage changes as the input grows.

Previous Next
Lesson Overview

What Is Space Complexity?

Space Complexity helps us understand how much memory an algorithm needs to solve a problem and how its memory usage grows as the input size increases.

Space Complexity describes how much memory an algorithm needs while it runs, depending on the size of its input.

An algorithm may need only a few variables, or it may need to create arrays, objects, matrices, or additional data structures. Space complexity helps us understand how these memory requirements grow.

Memory Usage
Input Size Memory Required

Memory Usage

Measures the memory required by an algorithm during execution.

Growing Input

Explains how memory requirements change when the input size increases.

Memory Efficiency

Helps compare algorithms that solve the same problem but use different amounts of memory.

Important:

Space complexity is about how memory usage grows with the input size, not simply the total number of bytes used on one particular computer.

Core Concepts

Total Space vs. Auxiliary Space

When analyzing an algorithm's memory usage, it is useful to distinguish between the total memory required and the extra memory created by the algorithm itself.

Total Space Complexity

Includes the memory needed for the input and the additional memory used during execution.

Total Space = Input Space + Auxiliary Space
Example:

An algorithm receives an array of 100 numbers and creates another array to store its results.

Auxiliary Space

Refers to the extra memory used by an algorithm, excluding the input storage itself.

Auxiliary Space = Extra Memory
Example:

An algorithm uses a few variables to calculate the sum of an existing array without creating another array.

Remember:

Some explanations use "space complexity" to refer to auxiliary space. Always check whether the input memory is included in the analysis.

Complexity Classes

Common Space Complexity Classes

Space complexity is commonly expressed using Big O notation. The notation describes how memory requirements grow as the input size \(n\) increases.

O(1)

Constant Space

Memory usage stays constant as input grows.

Example: Using a fixed number of variables to calculate a sum.

O(n)

Linear Space

Memory grows proportionally to input size.

Example: Creating an array that stores \(n\) numbers.

O(n²)

Quadratic Space

Memory grows proportionally to \(n \times n\).

Example: Creating an \(n \times n\) matrix.

Space Complexity Comparison

Complexity Meaning For n = 5 Typical Example
O(1) Constant memory Fixed number of variables Sum using a few variables
O(n) Linear memory 5 stored elements One-dimensional array
O(n²) Quadratic memory 25 stored elements 5 × 5 matrix
Keep in mind:

These examples describe the amount of stored data in common cases. Actual space complexity depends on the variables, data structures, and operations used by the algorithm.

Practical Example 01

Understanding O(1) Space Complexity

Consider a function that calculates the sum of all numbers in an array. It uses a variable named sum to store the result.

sum.js
JavaScript 
function calculateSum(numbers) {
    let sum = 0;

    for (let i = 0; i < numbers.length; i++) {
        sum += numbers[i];
    }

    return sum;
}

console.log(calculateSum([2, 4, 6, 8]));
01

Input Array

The function receives an existing array. The array contains the input values.

02

Fixed Variables

The function uses sum and i. It does not create a new array that grows with the input.

03

Constant Auxiliary Space

Even if the input contains thousands of numbers, the function still uses a fixed number of additional variables.

Space Complexity: O(1)

The auxiliary memory remains constant as the input size grows. The loop affects the running time, but the loop itself does not require a growing amount of additional memory.

Practical Example 02

Understanding O(n) Space Complexity

Now consider a function that creates a new array and stores the numbers from 1 to \(n\). The new array grows whenever the input size increases.

createNumbers.js
JavaScript 
function createNumbers(n) {
    const numbers = [];

    for (let i = 1; i <= n; i++) {
        numbers.push(i);
    }

    return numbers;
}

console.log(createNumbers(5));
01

Create an Empty Array

The function starts with an empty array named numbers.

02

Store Each Number

Every loop iteration adds another element to the array.

03

Memory Grows with n

If \(n = 5\), the array stores five elements. If \(n = 100\), it stores one hundred elements.

Visualizing Array Growth

n = 3
1 2 3
3 elements
n = 5
1 2 3 4 5
5 elements
n = 8
1 2 3 4 5 6 7 8
8 elements

Space Complexity: O(n)

The function creates an array containing \(n\) elements. When the input size doubles, the number of stored elements also doubles.

Practical Example 03

Understanding O(n²) Space Complexity

A two-dimensional matrix can require quadratic space when it contains \(n\) rows and \(n\) columns.

createMatrix.js
JavaScript 
function createMatrix(n) {
    const matrix = [];

    for (let row = 0; row < n; row++) {
        const currentRow = [];

        for (let column = 0; column < n; column++) {
            currentRow.push(0);
        }

        matrix.push(currentRow);
    }

    return matrix;
}

console.log(createMatrix(3));

A 3 × 3 Matrix

When \(n = 3\), the matrix contains 3 rows and 3 columns, giving us 9 elements.

0 0 0 0 0 0 0 0 0
Rows 3 × Columns 3 = 9 Elements
01

Create the Matrix

The function creates an outer array that will hold all the rows.

02

Create Each Row

For every row, the function creates another array and fills it with \(n\) elements.

03

Calculate the Stored Elements

An \(n \times n\) matrix contains \(n^2\) elements. For example, a 10 × 10 matrix contains 100 elements.

Space Complexity: O(n²)

The matrix stores \(n^2\) elements. Doubling the input dimension makes the number of matrix elements four times larger.

Common Mistake

Does Every Loop Increase Space Complexity?

No. A loop does not automatically increase space complexity. What matters is whether the algorithm creates or stores additional data as it runs.

O(1)

Loop with Constant Space

printNumbers.js 
function printNumbers(n) {
    for (let i = 1; i <= n; i++) {
        console.log(i);
    }
}

The function prints each number without storing all the numbers in a new data structure. Its auxiliary space is O(1).

O(n)

Loop with Linear Space

saveNumbers.js 
function saveNumbers(n) {
    const numbers = [];

    for (let i = 1; i <= n; i++) {
        numbers.push(i);
    }

    return numbers;
}

This function stores every number in an array. The array grows with the input size, so its auxiliary space is O(n).

The main idea:

Time complexity asks how the amount of work grows. Space complexity asks how the additional memory grows. A loop can increase time without increasing auxiliary space.

Analysis Guide

How to Analyze Space Complexity

To estimate an algorithm's space complexity, inspect the variables, data structures, and function calls it uses.

01

Identify the Input Size

Determine the input size and represent it using \(n\).

02

Count Additional Variables

Check whether the algorithm uses a fixed number of variables or creates more variables as the input grows.

03

Inspect Data Structures

Look for arrays, objects, sets, maps, matrices, or other structures that store additional data.

04

Check Recursion

Recursive calls may create stack frames that remain in memory until those calls return.

05

Express the Growth

Use Big O notation to describe how the additional memory grows with the input size.

Example: Recursion and the Call Stack

Each active recursive call needs a stack frame. In this countdown example, the maximum number of active calls grows with \(n\).

countDown.js
JavaScript 
function countDown(n) {
    if (n === 0) {
        return;
    }

    countDown(n - 1);
}

countDown(3);

Call Stack for countDown(3)

Call 1 countDown(3)
Call 2 countDown(2)
Call 3 countDown(1)
Call 4 countDown(0)

Each call waits for the next call to finish before returning.

Auxiliary Space: O(n)

The recursion depth grows with \(n\). Therefore, the call stack requires O(n) additional space, assuming each stack frame uses constant space.

Important:

Recursion does not always require O(n) space. The space complexity depends on the maximum recursion depth and the memory used by each call.

Comparison

Space Complexity vs. Time Complexity

Time and space complexity measure different aspects of an algorithm. An algorithm can be fast but require more memory, or use less memory while performing more work.

Aspect Time Complexity Space Complexity
Measures How the amount of work grows How memory usage grows
Main concern Execution efficiency Memory efficiency
Common examples O(1), O(n), O(n²) O(1), O(n), O(n²)
What to inspect Operations and loops Variables, data structures, and recursion
Key question How much work is performed? How much additional memory is needed?
Remember:

A nested loop often increases running time, but it does not necessarily create quadratic space. Always analyze memory usage separately from execution time.

Summary

Key Takeaways

Review the key principles of Space Complexity and learn how to identify memory usage patterns, recognize common complexity classes, and analyze the extra space an algorithm requires.

Space complexity describes how memory requirements grow with input size.

Total space includes input storage and auxiliary space, while auxiliary space focuses on additional memory.

O(1) means constant additional memory, O(n) means linear additional memory, and O(n²) means quadratic additional memory.

A loop does not automatically increase space complexity. Check what the algorithm stores.

Recursion can consume additional memory through the call stack.

Analyze time complexity and space complexity separately because they measure different things.
